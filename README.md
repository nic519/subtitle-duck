# 字幕鸭（Subtitle Duck）

<img src="assets/app-icon.png" alt="字幕鸭应用图标" width="160">

**把本地视频的字幕生成、翻译、局部修补和视频封装，放进一个桌面工具。**

字幕鸭面向需要给视频制作字幕、翻译外语字幕，或补齐已有字幕片段的用户。通过文件拖入、视频预览和分步骤操作，完成从视频到 SRT，再到带字幕 MKV 的处理流程；识别环境与模型也可以直接在应用内准备。

语音识别、字幕文件合并和视频封装在本机完成。字幕翻译使用在线 Google 翻译服务，会将待翻译的字幕文本发送至该服务。

## 项目亮点

- **本地识别，环境可托管**：基于 faster-whisper，一键准备 Python、识别依赖和模型，完成实际加载与短音频转写校验后启用。环境与模型准备好后可离线生成字幕。
- **整片、片段、批量三种处理方式**：可以识别完整视频，也可以在预览中选择多个时间片段，或将多个视频加入串行队列逐个处理。
- **局部重做不用从头开始**：片段字幕保留原视频时间轴，另存后可通过独立工具替换完整字幕中的对应区间，适合修补漏译、漏识别的部分。
- **视频与字幕软合并**：将字幕作为独立轨道嵌入 MKV 视频，不把文字烧录到画面上；可在支持的播放器中选择或关闭字幕。音视频流直接复制，无需重编码，避免画质损失。
- **长任务有反馈、可控制**：识别、翻译、安装和模型下载提供进度与取消操作；应用内切换工具页保留任务状态，批量识别重新开始时跳过已成功的文件。
- **常用操作集中，诊断按需展开**：支持拖拽、文件选择、粘贴路径和打开结果所在位置；命令与日志可供排查，宽窄窗口使用同一套步骤布局。

## 功能一览

| 工具 | 输入 | 输出与用途 | 依赖 |
| --- | --- | --- | --- |
| 字幕生成 | 单个视频、多个视频或选定片段 | 原视频时间轴上的 SRT 字幕 | FFmpeg、faster-whisper 环境与模型 |
| 字幕翻译 | SRT 字幕 | 保留时间轴、按目标语言另存的 SRT | 可访问 Google 翻译的网络 |
| 视字合并 | 视频 + SRT / ASS / SSA 字幕 | 软合并为带独立字幕轨的 MKV，不烧录画面 | FFmpeg |
| 字幕合并 | 局部字幕 A + 完整字幕 B，均为 SRT | 用 A 覆盖 B 对应时间区间后的新 SRT | 无需识别模型 |

### 字幕生成：从预览选段到批量转写

在“字幕生成”中拖入或选择视频，准备好识别环境后即可开始。

- **自动检测语言**：识别任务使用转写模式；通用 Whisper 模型用于生成原文字幕，需要译文时再使用“字幕翻译”。
- **预览与定位**：播放、暂停、时间轴定位，支持 0.1 秒微调和 5 秒快进/快退，并可将当前播放位置设为片段起止点。预览包含 FFmpeg 兼容处理路径。
- **多片段生成**：同一视频可选择多个不重叠片段，按时间顺序识别，结果仍对齐原视频时间，不必手动重新偏移。
- **独立保存结果**：识别字幕另存为 SRT，遇到已有文件会避让命名，不自动覆盖或合并已有字幕。部分片段失败或停止时，已完成片段仍可形成结果，并显示未完成情况。
- **批量队列**：一次导入多个视频，逐个识别全片，分别显示进度、状态和输出。单个文件失败后继续后续文件；重新开始只处理未成功项。批量模式使用全片识别，选段用于单视频模式。
- **手动配置入口**：已有环境可指定 Python 和本地 CT2 模型目录，也可从成功使用过的模型历史中快速选择。

当前识别实现使用 CPU / INT8，并启用语音活动检测（VAD）。处理速度取决于视频时长、模型大小和本机性能；界面没有 GPU 加速配置入口。

### 字幕翻译：保留时间轴，按语言导出

导入 SRT，选择中文、英语、日语或韩语作为目标语言，开始翻译后即可查看进度，也可以中途停止。

- 自动检测源语言，保留字幕时间轴与条目结构。
- 支持调整每批翻译字符数，集中处理字幕文本。
- 支持应用内代理开关、代理地址和连接测试。
- 结果保存在源文件所在目录，例如 `movie.srt` 翻译为中文后输出 `movie.zh.srt`。

翻译无需安装识别模型，但需要网络。同一源文件重复翻译到同一语言会写入同名译文文件；如需保留上一版译文，请先重命名或备份。

### 视字合并：软合并，嵌入独立字幕轨道

**这是软合并：字幕嵌入视频文件，作为独立字幕轨道保存，不会直接写到视频画面上，也不提供硬字幕烧录。** 在支持的播放器中，可以选择或关闭这条字幕轨。

在共用拖拽区**同时拖入一个视频和一份字幕**，应用会按文件类型自动分配；也可以分别选择文件或粘贴路径。

- 视频入口支持 `.mp4`、`.mkv`、`.avi`、`.mov`、`.wmv`、`.m4v`、`.ts`。
- 字幕入口支持 `.srt`、`.ass`、`.ssa`。
- 使用 FFmpeg 的流复制方式输出 `原文件名.muxed.mkv`，显示处理进度与速度。
- 输出文件已存在时停止并提示，避免覆盖。

具体媒体能否成功处理仍取决于 FFmpeg 与容器对实际编码的支持；字幕的显示与样式取决于播放器对字幕轨道和格式的支持。

### 字幕合并：修补已有字幕

“字幕生成”页面下方提供独立的 SRT 合并工具，无需先生成字幕，也无需准备识别模型。

1. 选择局部字幕 **A**，也可以使用刚生成的字幕。
2. 选择完整字幕 **B**；两份字幕必须使用同一原视频时间轴。
3. 点击“合并并另存”，结果保存在 B 所在目录，命名为 `原文件名-合并.srt`，重名时追加序号。

合并以 **A 最早开始到最晚结束的整个区间**覆盖 B，包含 A 各条字幕之间的空隙；保留 B 的其余部分，A、B 原文件均不修改。因此，若 A 含有相距很远的多个片段，请确认它们之间的内容也应被替换。

## 快速开始

### 获取应用

前往 [GitHub Releases](https://github.com/nic519/subtitle-duck/releases) 查看已发布版本与附件。当前仓库的自动发布流程面向：

| 平台 | 发布流程产物 |
| --- | --- |
| macOS Apple Silicon（arm64） | DMG |
| Windows x64 | EXE 安装程序 |

项目也包含 Linux 构建配置，但当前发布流程不提供 Linux 安装包，`package` 脚本仅处理 macOS 与 Windows。macOS 构建目前未配置代码签名与公证。构建配置或安装包生成成功不等于所有平台功能均已完成真实桌面验收。

### 第一次生成字幕

1. 打开“字幕生成”，拖入一个视频。
2. 如未检测到 FFmpeg，使用应用内的“安装 FFmpeg”，或手动指定已有可执行文件。
3. 选择识别模型，点击“一键准备识别”，等待环境安装、模型下载和校验完成。
4. 选择全片或所需片段，开始生成，完成后打开 SRT 结果。
5. 如需译文，将结果导入“字幕翻译”；如需将字幕嵌入视频文件，再到“视字合并”选择视频与字幕，点击“开始软合并”（字幕不会烧录到画面上）。

首次准备识别环境需要联网和额外磁盘空间。模型与 Python 运行环境按需下载，不随应用安装包分发。

## 环境与模型管理

### FFmpeg

应用优先检测本机 FFmpeg；未找到时，可下载当前平台对应的 FFmpeg 与 ffprobe，校验并验证运行后自动配置。支持进度、取消与失败重试，也保留手动路径入口。

自动安装文件保存在应用数据目录，不修改系统 PATH。下载版本、地址与 SHA-512 固定在 [FFmpeg 版本清单](src/desktop/ffmpeg/releases.json)，来源为 `@ffmpeg-installer` / `@ffprobe-installer` 平台包。安装器覆盖 macOS / Linux 的 arm64、x64 及 Windows x64；其他架构需手动配置。这是组件安装器的范围，不代表均有对应应用发行包。

### Faster Whisper

“一键准备识别”依次完成 uv 检测、Python 与 faster-whisper 安装、所选模型下载，以及模型加载和短音频转写验证，通过后自动启用。

- 优先复用 PATH、Homebrew、`~/.local/bin` 或 `~/.cargo/bin` 中可运行的 uv（最低 0.6）；找不到时下载固定版本并校验 SHA-256。
- Python 3.12、隔离环境、下载缓存和模型存放在 Electrobun 的 `Utils.paths.userData/faster-whisper` 下，不修改系统 Python，不要求管理员权限。
- 依赖版本与哈希由 [requirements.lock](resources/faster-whisper/requirements.lock) 固定；支持官方 PyPI 和清华镜像，仅作用于此次安装，不修改系统 pip / uv 配置。
- 可单独安装环境或下载模型。**选择下载项不会改变当前模型配置**，单独下载完成后需点击“使用此模型”；“一键准备识别”则在全部校验通过后自动启用。
- 下载重试复用已校验的完整文件，当前文件中断后重新下载；有可用托管环境时，模型下载完成前会执行实际加载与短静音转写校验。
- 安装显示耗时与最近输出；子进程连续 3 分钟无输出或运行超过 10 分钟会停止并提示重试，取消时会清理未正常退出的子进程。

Windows / Linux 的环境安装与识别仍需在对应系统验证，macOS 的本地验证不能替代跨平台验收。

## 技术架构

| 层级 | 实现 |
| --- | --- |
| 界面 | React 18、TypeScript、Tailwind CSS、Radix UI、Lucide 图标 |
| 前端构建 | Vite |
| 桌面运行时 | Electrobun 2.0.4，Bun 主进程，系统 WebView |
| 媒体处理 | FFmpeg / ffprobe，本地媒体预览与兼容处理 |
| 语音识别 | Python、faster-whisper、CTranslate2 模型 |
| 翻译 | Google 翻译文本接口，应用内代理与请求队列 |
| 开发与验证 | Bun 依赖管理、Bun Test、TypeScript 检查、GitHub Actions |

界面通过类型化 RPC 调用桌面主进程，由主进程处理本地文件、媒体任务、子进程和网络请求。工作流状态与页面展示分离，避免切换工具页时丢失正在执行的任务。macOS 文件拖放另有原生桥接，用于获取本地文件路径。

```text
src/
├── pages/subtitle-mux/    # 三个工具页、模型管理、时间轴与字幕合并面板
├── subtitle-mux/          # 工作流状态、批量队列、片段与翻译逻辑
├── desktop/
│   ├── ffmpeg/            # FFmpeg / ffprobe 检测与托管安装
│   ├── transcription/     # 识别环境、模型管理、转写与时间轴处理
│   ├── subtitles/         # 视频封装、字幕翻译、SRT 文件合并
│   └── file-drop/         # 本地文件拖放与原生桥接
└── components/           # 共用步骤、文件输入、视频信息与基础控件
native/macos/             # macOS 原生文件拖放桥接
resources/faster-whisper/ # Python 依赖声明与锁文件
scripts/                  # 开发启动、构建、打包与本地验证
.github/workflows/        # 测试、构建及标签发布流程
```

## 本地开发

开发环境需要 Bun；CI 当前使用 Bun 1.3.14。在项目目录执行：

```bash
bun install
bun run dev
```

首次运行开发或构建命令会通过 `electrobun sync` 下载配套工具链并生成 `.hutch/devkit`，需要网络。该目录不提交，项目依赖由 `package.json` 与 `bun.lock` 管理。

| 命令 | 用途 |
| --- | --- |
| `bun run dev` | 启动桌面开发环境，准备原生拖放桥接 |
| `bun run build:renderer` | TypeScript 检查与前端构建 |
| `bun run build` | 构建当前平台的桌面应用 |
| `bun run build:release` | 构建 stable 发布版本 |
| `bun run verify` | 启动并验证当前平台已有的本地构建 |
| `bun run package` | 构建发布版本并执行当前平台打包脚本 |
| `bun test` | 运行测试 |

Windows 的 EXE 安装程序由发布工作流额外调用 Inno Setup 生成。推送标签触发测试与构建，再生成 macOS / Windows 产物并发布 GitHub Release；具体步骤见 [发布工作流](.github/workflows/build-on-tag.yml)。

### 验证与维护

测试覆盖字幕时间轴与片段处理、批量队列、翻译、文件合并、媒体预览、环境安装、任务取消和文件拖放等逻辑。提交变更前按影响范围运行测试与构建：

```bash
bun test
bun run build
```

界面变更还应检查空态、已选文件、宽窄窗口及相关交互。浏览器模拟与真实桌面验证分别记录，尤其不能将模拟拖拽视为原生文件拖拽验收。项目交互与功能约定见 [AGENTS.md](AGENTS.md)。

更新 Python 依赖时，从 `resources/faster-whisper/requirements.in` 重新生成锁文件并验证；更新 FFmpeg 清单时，同时验证 FFmpeg、ffprobe 的实际执行和媒体处理。
